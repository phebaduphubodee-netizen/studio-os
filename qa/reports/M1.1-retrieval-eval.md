# M1.1 Retrieval Eval — 2026-07-02

**Setup:** `scripts/vault_search.py` (BM25, pure stdlib, per-section + whole-file
docs, path tokens ×3, Thai via char-bigrams) over `knowledge/` + `docs/`.
Question set: `qa/golden-set/retrieval-questions.json` (20 questions).
Metric: hit@3 — an acceptable source path cited in the top-3 results.
Runner: `python3 scripts/eval_retrieval.py` (exit 0 iff ≥90%).

**Result: 20/20 = 100%** (gate ≥90%). Progression during tuning:
- 18/20 baseline (card templates missed — query terms lived only in filenames)
- 17/20 after removing `_vault-CLAUDE-v2.2.md` noise from the index —
  the removal exposed that two earlier passes were citing the noise file
- 18/20 after indexing path tokens; 20/20 after weighting path tokens ×3

**Caveats (honest):**
1. BM25-only. The blueprint's hybrid (dense + RRF + cross-encoder rerank) is a
   later Phase 1 upgrade; the CLI contract (`path#Lline` citations) is stable.
2. The index was tuned against this same question set. Future tuning needs a
   fresh holdout; grow the set as codes-th fills (M1.2) before re-tuning.
3. hit@3 is a proxy for "answers with correct citation" (M1.1 wording). The
   full test is the `knowledge-manager` agent answering with citations; spot-
   check that flow after the next session restart loads the agent.
4. Corpus is small (~60 md files). Scores will shift as _inbox is ingested.
