# Scrutiny report — commit 019a67f (v004 promotion, camera v0.4, suite_clearance v0.3)

Cold outside review, 2026-07-02. Method: 3 independent cold-reader agents (camera math /
clearance+citations / registry seam) + one adversarial verifier per finding, every finding
reproduced by probe or live run before acceptance; plus an independent pure-python replica of
the v0.4 lens solve confirming the claimed 26/35 mm picks on both shipped specs.
12 findings CONFIRMED, 1 refuted. Verdict: **FIX-THEN-SHIP** — the committed behavior works on
both shipped specs, but the clearance engine now prints a false legal-measurement label, and the
new lens solve has a real divergent-case bug.

## Introduced or worsened by 019a67f

### 1. BLOCKER — ceiling check compares CLEAR height against the floor-to-floor statute and labels it "ระยะดิ่ง พื้นถึงพื้น"
`suite_clearance.py:45-46,118-126`. spec `room.ceiling_mm` is clear interior height (walls are
built at that h — `build_room.py:1242,1339`), but it is compared against ฉ.55 ข้อ 22's 2600 mm
which is **พื้นถึงพื้น** (dimensional_rules note: "NOT clear ceiling height — do not conflate").
Reproduced: a legal Bangkok condo (clear 2500 under a 2700 floor-to-floor slab) → `FAIL` asserting
a statutory violation that does not exist. Error direction is FAIL-only (clear ≤ floor-to-floor,
never a false pass), but every PASS line now stamps a clear-height number with a floor-to-floor
label. The commit's docstring claims the floor-to-floor semantics were FIXED — only the cite text
changed — and it also removed the old "UNVERIFIED vs ratchakitcha" hedge, upgrading the confidence
of a wrong-basis check. **Fix:** compare `ceiling_mm + assumed slab` (or require a
`floor_to_floor_mm` spec field), or keep the conservative proxy but print it honestly:
"clear 2800 ≥ 2600 f2f floor ⇒ conservative pass (proxy)".

### 2. MAJOR — v0.4 lens solve mixes two subjects
`build_room.py:370,434-440`. `standoff` is measured to `main` (largest item **including rugs**);
`req_w` is sized from the largest **non-rug** item. Probe-confirmed divergent case (living/dining,
dining rug far zone, sofa near zone): camera aims at the empty rug, solves 50 mm from
distance-to-rug over size-of-sofa, and the sofa that sized the lens is 56° off-axis — fully out of
frame — feeding the paid Gemini pass a long-lens shot of an empty rug. Shipped `living_condo.json`
already has `main`=rug ≠ `subj`=sofa (2600×3200 rug > sofa); it survives only because they are
colocated (actual frame at sofa = 1.76×, not the documented ~2×). **Fix:** one-line — use the same
non-rug filter for `main` at line 370.

### 3. MINOR — rug overlap whitelist broader than its stated intent
`suite_clearance.py:156-157` skips ANY pair containing a rug: rug-under-builtin millwork
(buildability conflict) and rug-over-rug now silently PASS; v0.2 warned on both.
**Fix:** whitelist only pairs where the other piece is `_grp == "item"`.

### 4. MINOR — v004.json provenance is factually false (and immutable)
`v004.json:18` says "both v003 promotions scored styling 3/5" — actually a **5/3 split** (bedroom
v003 styling 5/5 SHIP on disk). labels.json, strategy.md and the commit message all say 5/3;
the immutable payload contradicts its own commit and steers future styling iteration wrong for
bedroom (v004's styling additions coincided with bedroom dropping 5/5→4.5). **Fix:** errata note
in labels.json/README (versions stay immutable) + correct it in v005's provenance.

### 5. MINOR — production label now rests on zero SHIP verdicts
Promotion rule is score-only (≥4/5 ×2 room types) and was met, but both v004 evidence runs are
verdicted REWORK — a class `critique.py:201` defines as NOT_READY. v003 had 1×SHIP; v004 is the
first zero-SHIP production. Human-QA guard still applies (output is DRAFT until critique + human
QA), so non-blocking — but the rule and the gate's own taxonomy now disagree. **Fix (policy):**
require ≥1 SHIP among the evidence runs, or explicitly state in the rule that verdict tier is
advisory.

### 6. NIT — commit message claims "Same thresholds, same verdicts (smoke both specs)" — false
The rug whitelist flips living_condo REVIEW→PASS (reproduced against `019a67f^`). strategy.md in
the same commit records it honestly; only the commit message misleads a git-history auditor.

### 7. NIT — module-level `RULES_TH = _load_rules()` import-time dependency
Copying the engine alone (its stated engine-agnostic purpose), or renaming a JSON key, crashes
`suite_clearance` + `suite_lighting` + `suite_package` at import. Loud and immediate — acceptable,
but noted; version-pinned filename also means every rules bump edits the engine.

## Preexisting, surfaced by this review (not caused by 019a67f)

### 8. MAJOR — loaded statutory rules are dead code
`bedroom_width_min` 2500 (ฉ.55 ข้อ 20), `corridor_min` 1000 (ข้อ 21), `circulation_min` 900 are
loaded into RULES_TH and enforced NOWHERE. Reproduced: a 2400×3400 bedroom (narrow side < 2500,
illegal under the very ข้อ 20 the output cites) → clean cited PASS. `condo_unit_area_min` (ข้อ 19)
likewise never applied. This is exactly the Gate-0/M3.1-full work — should be the next slice.

### 9. MAJOR — `_point_in_poly` boundary asymmetry gives wrong FAIL on east/north flush placement
Corners exactly on max-x/max-y walls test "outside" (probe: `(5500,2000)`→False, `(0,2000)`→True).
Mirroring bedroom_suite's passing west-wall wardrobe to the east wall → verdict FAIL for a legal
flush built-in; propagates into the client QA sheet via `suite_package`. (Already bitten once:
the TV wall was moved to 6790 for this reason.) **Fix:** epsilon-inflate the outline or treat
boundary as inside.

### 10. MINOR — ข้อ 20 area check counts sub-room footprints and applies the bedroom statute to every room type
10 m² outline containing a 3 m² ensuite → "10.0 m² vs 8 m² min" PASS while the bedroom proper is
7 m² (false statutory pass); a 7 m² study WARNs citing the bedroom statute; living_condo already
gets the bedroom cite today.

### 11. MINOR — line-of-sight sampling (19 points) steps over thin full-height blockers
Blockers thinner than ~standoff/20 (≈0.24 m at living's standoff) can be missed; 100 mm full-height
builtins are in-distribution (bedroom_suite has one). Probe: camera behind a 100 mm partition
chosen as "clear", rendering the wall's back at 50 mm. **Fix:** segment-vs-box intersection
instead of point sampling.

### 12. NIT — degenerate fallbacks: empty-candidate camera lands on the target (standoff 0, zero view vector); h-less rug becomes a stand block (default 400 mm) though rendered 14 mm thick.

## FIX OUTCOMES (same day, applied on "ลุย" — commit follows this report)

All 12 confirmed findings addressed; every fix adversarially re-verified by a second
3-agent workflow (29 regression/attack scenarios) plus live probes. Round-2 verification
caught 4 real defects **in the first round of fixes themselves**; round 3 was forced by
the gate. Final state:

- **F1 ceiling (blocker)** — ข้อ 22 checked on its own basis: `floor_to_floor_mm` field
  (statutory PASS/FAIL) or clear-height proxy (≥2600 = a-fortiori PASS; <2600 = WARN,
  never a false statutory FAIL); missing/invalid data now FAILs loudly instead of
  reading as a 0 mm measurement. Wet rooms unchanged (ฉ.39 is floor-to-ceiling).
- **F2 lens/aim (major) — the interesting one.** Round-1 fix (aim at largest non-rug)
  passed all static probes, then the gate REFUTED it: 28 mm sofa-aim scored **2.5/5**
  ("awkward, cramped, cuts key elements") vs the promoted 35 mm rug-aim 4/5. Evidence
  says a group-rug approximates the furniture GROUP's footprint. Final rule: aim at the
  largest item **only if it is a rug the hero (largest non-rug) piece actually sits
  on**; otherwise aim at the hero. Verified: both gated cameras reproduce
  **pixel-identically** (living clay max-diff 0 vs the promoted run) and the divergent
  far-dining-rug case now aims at the sofa (50 mm, 2.3× frame). Negative evidence kept:
  `room_living_condo_eye_hybrid_v004b.{png,critique.json}`.
- **F3 rug whitelist** — scoped to loose-furniture pairs; rug-under-builtin and
  rug-on-rug warn again. Same one-line class fix applied to `clearance_check.py`.
- **F4 provenance** — `_errata_v004` in labels.json (versions immutable).
- **F5 rule-vs-verdict** — `_promotion_rule` now states scores are operative, verdict
  strings advisory, human QA mandatory.
- **F8 dead rules (slice)** — ข้อ 20 enforced: net-of-subrooms area + narrow side.
  Tiered detection (round-2 fix): bedroom-NAMED type → statutory FAIL tier; bed item in
  a non-bedroom-named room → WARN tier (daybed ≠ bedroom); neither → informational line
  that discloses the heuristic instead of asserting non-applicability. corridor/
  circulation stay loaded-not-enforced, and the footer now says exactly that.
- **F9 boundary** — `_inside_or_on` (0.5 mm edge tolerance): flush east/north = legal;
  1 mm past the wall still FAILs.
- **F10 area basis** — net of sub-rooms; non-bedrooms no longer get the bedroom cite.
- **F11 LoS** — exact Liang-Barsky segment-vs-box replaces 19-point sampling (t=0.95
  clip so near-target millwork doesn't reject every spot).
- **F12 degenerate camera** — empty-candidate fallback REMOVED: loud SystemExit instead
  of silently feeding a garbage frame to the paid pass.
- **Narrow-side honesty rule (round 2):** bbox < 2500 proves a breach (FAIL); bbox
  ≥ 2500 on a true rectangle with no sub-rooms proves compliance (PASS); anything
  concave/carved is **WARN (unproven)** — bbox can only err toward false PASS there.

**Deliberate verdict change (disclosed, unlike 019a67f's commit message):**
`bedroom_suite` is now **REVIEW (0 fail, 1 warn)** — the ensuite carves the room, so

**Remaining open (recorded, not fixed here):** true rectilinear min-leg-width for
