## 1. THE ORIENTATION QUESTION, WHICH WAS BEING ASKED AS A SHAPE QUESTION

r33 offered a real bench mesh (622 x 433 mm) to this room's bed-end bench slot
(498 x 1000 mm) and `model_fit` refused it at **35% fill**. The arithmetic is
right and the question is wrong: the slot is long on **Y** because the bed's foot
runs that way, and no bench in any catalogue is exported long on its own Y. The
mesh did not need to be a different bench. It needed to be turned.

`millwork.orient_to_slot` (PURE, 7 tests) turns the mesh a quarter and fits it to
the **swapped** slot — which lands the world footprint back inside the drawn rect,
so nothing overflows. Measured across the cached shelf:

| candidate | before | after |
|---|---|---|
| `Ottoman_01` (CC0) | reject | **PASS 0.802** |
| `e73605b0` | reject | PASS 0.791 |
| `250b8e09` | reject | PASS 0.769 |
| `37c1bc3a` | reject 35% | PASS 1.150 |
| `125e8377` | reject | still refused — 274 mm against a 450 mm slot, a real height mismatch |

**The guard that keeps this honest** is derived from `model_fit`'s own docstring
rather than chosen: a spec item's w/d are the piece's LOCAL un-rotated dims, and
the generator PRE-SWAPS them for a cardinal 90/270 so fit-then-rotate lands the
world AABB on the drawn bbox. Turning again there would double-apply that swap.
So `orient_to_slot` refuses to fire on 90/270 and says so. **Verified against the
built scene, not assumed:** the stool (rot 270, spec 510 x 546) lands 546 mm on
world x — the pre-swap holds — while the bench (no rot) lands exactly its declared
498 x 1000. r33's note claimed this spec stores world footprints; that is refuted
for the acquire path and true for the bespoke builders, which is the actual finding:
**one field means two things depending on which builder reads it, and no
non-square rot'd item has ever gone through `place_model` to force the question.**

## 2. THE NIGHTSTAND BLOCKER WAS NEVER `model_fit` EITHER

All three bought nightstands PASSED it at r33. The eye threw them out anyway —
*"มันใส่วัสดุของตัวเองมา"* — because the acquire path had a material policy for
`_UPHOLSTERED` and **nothing at all for anything else**, so a bought cabinet
arrived in a stranger's oak against the signed D3-3 matte-dark and D1-A's rule
that this room must not become a fifth oak mass.

`_CASE_GOODS` adds that policy, derived exactly as the upholstery one is
(`asset_scale.carries_a_pbr_surface`): **KEEP an incoming surface that exists,
REPLACE one that does not.** `ClassicNightstand_01` has normal + metallicRoughness
maps, so its relief survives and only its colour moves to `nightstand_body` — the
**same call** the hand-built cabinet makes, so the bought and the built cannot
drift apart inside one frame. A kind in neither family now PRINTS that it has no
policy instead of quietly keeping the uploader's finish.

## 3. THE ONE THE MEASUREMENT WOULD NEVER HAVE FOUND, AND THE ONE THE EYE WOULD NEVER HAVE SIZED

The first acquired frame came back with the bench as **the brightest mass in the
room**. The DD forbids that in words: the bench is *"the DEEPEST value in the
room's soft goods... do NOT lighten it toward the bedding"*.

Cause: with no element preset for this item, nothing passed an rgba, so
`_retint_upholstery` used its own default — the cream boucle written months ago

BUILT bench read the value ladder; the BOUGHT one did not. Same family as §2,

## 4. WHAT THE BENCH CARRIES DOES NOT LEAVE WITH THE MESH IT SAT ON

p2r33 lost both brass lamps when the nightstands were swapped, and that was fixed.
The identical shape was still live one object away, and acquiring the bench fired
it:

- the throw looked up `bench__seat` **by name, with no `else`** — an acquired
  bench is named `bench__acq*`, so the throw was dropped **silently**. Measured:
  D7 went 7 loose items to 6 with nothing in the log to say why.
- the books sat at `bz0 = bh`, a **typed** z off the spec's declared height. The
  acquired ottoman fits to **501 mm** in a 450 mm slot (inside `model_fit`'s
  0.65-1.30 band), so both books would have been buried inside it.

Both now derive from the bench mass actually in the scene, whichever it is, and
the build prints `bench top MEASURED at 501 mm, not the spec's declared 450`. No
mass at all is announced rather than skipped. R9, one object further along.

## 5. WHAT I WOULD NOT SIGN, SAID BEFORE ANYONE ASKS

**`Ottoman_01` is a bulbous traditional pouf with bun feet in a modern slat-wall
suite.** The value is right now and the fit is right, and the FORM is, to my eye,
wrong for this room. I chose it on a measured discriminator — of nine candidates
that fit these slots, **only the two committed CC0 assets carry any PBR maps at
all**; every 3D Warehouse candidate is shape with flat base colours — and P2's own
exit test is texture coverage. That discriminator may be the wrong one *for
upholstery specifically*: this room has a SIGNED woven linen with real slub
relief, so `replace_material` on a plainer 3DW bench could beat keeping a
stranger's normal map. The measured alternatives are in §1 and cost one playblast
each to see.

This has NOT been through C2 or C3. It is a quick rung, and R5 says only
full fidelity closes a gate. The object question goes to the ladder and to his
eye; the mechanism below it does not depend on the answer.
