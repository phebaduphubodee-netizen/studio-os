# GATE — DELIV-001 · P2r50 · 2026-08-17

**The first rung on this lane that measures a NAMED OBJECT in the rendered picture —
and the negative control it was built with says the cut I was told to write is not
the cut the evidence supports.**

## What was asked, and what came back

The plan for this round was: build `bed_pixels.py`, measure the bed per object from
the id mask, **cut = mattress showing 0%**, wire it into the gate as blocking, then
run the cut backwards over p2r31…p2r49 — *"ถ้าใบไหนผ่าน แปลว่าเกณฑ์ผมผิด ต้องรายงาน
ก่อนแตะเรขาคณิต"*.

No frame passes. **But the criterion still turned out to be wrong, in the other
direction**, and the sweep found something nobody was looking for.

## 1 — The instrument

`pipeline/scripts/bed_pixels.py`, pure of `bpy`, spawned out of process by
`build_room._score_deliverable` after the render (layer law: it needs PIL and numpy,
which Blender's bundled Python does not have).

**Roles come from the MATERIAL, never from the object name.** R9b: *"a rule that
names the objects it applies to will always exempt the next one."* Surveyed across
all 96 scene dumps on disk, bed objects wear exactly six material tokens and nothing
else, in every round from p2r2 to p2r50. Two assertions keep the derivation from
going quietly blind and both fail closed: a roster with **no** core object REFUSES
(exit 2) rather than reporting 0%, and an object that **overlaps the mattress in
plan**, carries more than a sliver of pixels and wears a material no role claims is
a VIOLATION naming the material.

**It also splits the mattress's TOP plane from its FLANK**, by projecting the top
face and testing each core pixel against that quad. The projection is not trusted on
assertion: it must reproduce every large masked object's own pixel rows before any
split is reported, on every frame, or the split prints as unavailable.
`bed__headboard_welt_top` measures rows 727-744 and projects to 727-744. The sign of
`shift_y` alone is worth **384 px** on the hero frame — larger than the feature the
split exists to find — and that is how it was settled.

**Calibration against human eyes, which is the only one available.** On p2r47 —
the frame the three sighted readers actually judged — they put the lofted top layer
at 25 / 30 / 40 percent. The instrument, measuring duvet-material pixels over the
projected top plane, reads **40.9%**: inside their spread, at the top of it. That
also settles an ambiguity the duvet-share record flagged as open in its own words
(*"nothing here rectifies one to the other"*): plan 43.2 against image 40.9 is **2.3
points**, not the 15 one reader estimated.

## 2 — The negative control, which is the finding

Run over every frame in `pipeline/output` carrying a beauty frame, an id mask and a
scene dump:

| frame | core px | of sleeping surface | bare TOP | bare FLANK |
|---|---|---|---|---|
| p2r31e / f / r34 / r35 | 11,694 | 1.9% | 0 | 11,694 |
| p2r39 / r42 / r43 | ~14,100 | 2.3% | 0 | ~14,100 |
| p2r32 / r36 | 108,584 | 18.5% | 30,313 | 78,271 |
| p2r41 | 165,210 | 22.0% | 141,408 | 23,802 |
| **p2r44** | 332,879 | 56.7% | 37,218 | **295,661** |
| **p2r45** | 542,175 | 92.8% | 217,193 | **324,982** |
| **p2r47 / r49** | 270,691 | 44.0% | 15,842 | **254,849** |

A flat cut at the delivered value fails **15 of 15**. It separates nothing, because
a bare mattress flank is in every frame this studio has ever made — and a rung that
is red on every render is a rung somebody switches off, which R13 says in its own
words. **That is why the cut I was asked to write is not the one that shipped.**

What the same sweep shows instead is **a regression nothing caught: the bare flank
rose 23x, from 11,694 px to 295,661 px**, across the rounds that replaced hand-built
cloth with a bought set — while `coverage` read **94.0%** and `fall_sides` read
**4/4** the whole way, because both are computed in PLAN and a vertical flank has
zero plan area.

**So the rung BLOCKS on the number rising and on going blind; the absolute number
PRINTS on every run into the render path.** Baseline `qa/bed-pixels-baseline.json`,
policy `rule_gate.bed_exit_policy`, same three-code contract as R11's pixel rung
(0 hold · 1 rose-or-blind · 2 could-not-run). Proven both ways: it holds at p2r49,
bites at p2r44 and p2r45, refuses to compare across cameras and says so rather than
printing a pass.

## 3 — Where the target comes from (R4b: a cut is never typed by the builder)

Three fresh-context sighted readers, each given the seven delivered bedroom frames
plus our own p2r49 — unlabelled, in a different fixed order per reader, every frame
normalised to PNG at one long edge so neither format nor resolution could identify
ours. One written question: is any part of the mattress's vertical side face bare,
with a taut fitted sheet counting AS bare because it is the mattress's own shape and
not bedding laid over it.

    delivered   16 of 18 legible readings `none`, 2 `sliver`, NONE above sliver
    ours        `most` — 3 readers of 3, none of them told which frame was ours

Archived with every per-frame answer:
`_private/deliv-001/flank-panel-2026-08-17/readings.json`. It establishes a fact and
a direction, **not a pixel number** — the readers answer on a word scale and
delivered frames carry no object mask, so no delivered flank can be counted in
pixels. That limit is written into the record rather than rounded away.

## 4 — The thing that must not be misread

The hand-built cloth stack covered the mattress **23x better** than the bought set
does. **That is not an argument for reverting to hand-built cloth, and the row that
records it says so by name (D-104).** His order that the bed cloth is ACQUIRED is a
CLASS order, given twice, and R13 exists because this lane once read an instance
verdict as repealing it. What p2r31e proves is narrower and more useful: **core near
zero is reachable on this bed, this camera, this room** — so the target is a property
of the ASSET, and the acquisition now has an acceptance test it never had. It also
makes the 11 never-benched whole-bed folders the obvious next move: a whole bed
brings its own mattress, so our box leaves the frame rather than needing covering.

## 5 — The rung caught its own author

## 6 — What the pre-commit review changed

Two seams, both the shape this repo has already paid for twice — a rung that could
not run producing a number that reads exactly like evidence:

- **The scene dump had no provenance tie to the frame.** `compose` refuses a mask
  from another render (`value_probe`'s rule) but nothing checked the DUMP, which
  decides every role and the AABB the split projects from. Measured: p2r49's frame
  through p2r45's dump reports the core at **87.7%** instead of 44.0%, silently,
  with the ratchet printing `held`. Now exit 2.
- **A corrupt baseline crashed and exited 1** — this module's own code for "the bed
  got worse", so an unreadable file would have printed as a regression. Now exit 2.
  This is the identical defect found in `orders_check` the same hour.

Also: a `top_share` key whose denominator differed from the report's table was
deleted rather than documented, and the bed stop now prints the ladder's reason too
when both fire.
