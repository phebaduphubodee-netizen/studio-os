Every crop in `p2_exit.CROPS` is declared as a **fraction of the frame**. The owner
adopted a different camera on 2026-08-26 (D-152) and every frozen box slid onto other
objects in the same move. Nothing checked. Measured from the render's own matmask:

```
                    p2r77 (old camera)            p2r78rc (his camera)
rug_edge      0.8% rug   -> printed ROLLED   3.9% rug   -> printed ROLLED
              50% bed_base, 29% bench        93% open pile, no edge in the box
duvet_fold     21% duvet -> printed 2.11x     15% duvet -> printed 1.87x
              28% curtain, 22% floor          48% curtain, 22% floor
wood_boards    66% veneer                      63% veneer (+17% e5_pelmet)
```

`rug_edge` is the sharp one. Its declared cut is ≥3.0 px rise = ROLLED. At p2r77 it
passed by measuring **the bed plinth's edge against the rug**; at p2r78rc it passed by
measuring **pile noise in open rug with no boundary in the box at all**. In the same
frame C3 filed the rug as *"แบนราบเป็นส่วนหนึ่งของพื้นไม้ ไม่มีความหนาและขอบ"*. The eye and the
instrument were never in disagreement — the instrument was pointed somewhere else.

**AND THIS IS THE THIRD TIME THIS REPO FOUND THIS DEFECT.**

- `fdb6fae` (2026-08-16, p2r41) — cloth_edge's box held ONE material, no boundary in it
  at all: *"a working control proved the METHOD could see; nothing ever checked that the
  BOX HELD A BOUNDARY."* Fixed **for that one box**, recorded as a `retired_box` note.
- `1ecb152` (2026-08-17, p2r49) — `bed_pixels.py`'s own docstring: *"`p2_exit.duvet_fold`
  — the exit test's flagship crop, frozen in FRAME space — lands on 55.0% flat sheet,
  40.8% mattress, 0.9% duvet. It has been scoring OUR MATTRESS against THEIR COMFORTER."*
  Written into a **different module's prose** and never acted on.
- today.

Each time it was recorded as a sentence about the instance, never built as a rung that
checks every box. That is CLAUDE.md's own opening line — *this repo measured the same
defect three times* — and R9b's law: **a rule that names the objects it applies to will
always exempt the next one.**

**BUILT (D-153):** every entry that measures inside a typed box must declare
`subject_materials`; `_subject_share` reads the render's own matmask before the rung

bar. `test_every_box_rung_declares_its_subject` puts the requirement on the SHAPE of a
registry entry so the next box cannot be exempt. Already wired: `build_room.py:615` calls
this harness out of process on every full-fidelity render.

## 3. THE SECOND FINDING: THE HARNESS DECLARED ABSENT AN OBJECT BOTH CRITICS RANKED FIRST

`throw_weave`'s mask half named the single material `bed_throw`. The acquired leg dresses
the same object `acq_bed_throw`, the lookup missed, and the miss fell through to
`_absent_by_declaration` — so the rung printed **"N/A BY DECLARATION — absent by decision,
not unmeasured"** on a frame that renders that throw at 888–1195 × 946–1078 px.

That object is C2's #2 (*"พู่อ่านเป็นกระดูก ไม่ใช่ไหมพรม ... มันเป็นวัสดุที่แย่ที่สุดในเฟรม"*) and C3's #1,
and Gemini's closing line was *"ถ้าต้องเลือกแก้ข้อเดียว ให้แก้พู่ของผ้าคลุมเตียง"*.

**The mechanism is a namespace collision, not a stale register.**
`value_ladder.DECLARED_ABSENT` is keyed by **object** (`bed__duvet`, `bed__throw`); this
rung names a **material**; the lookup bridged them with a `bed__`→`bed_` string mangle.
On an acquired set that inverts the meaning: D-086 declares the OBJECT `bed__duvet`
absent *precisely because* the bought set is one fused mesh, and D-138 says in its own
words that that mesh **wears the material** `bed_duvet`. So the material renders 6.99% of
the frame while its object is correctly signed absent.

**BUILT (D-155):** every registry field that takes a material takes a **list** of the
names that can dress the same site; `_has_pixels` asks the frame first and the ledger only
when the frame says there are no pixels; `_absent_by_declaration` answers only when
**every** listed name is declared absent — one present leg makes the site present.

**Recovered by that fix, on the frame of record:**
- `throw_weave` mask half, unmeasurable for rounds: **3.682x** the delivered comforter's
  fold energy (the box half reads 1.644x). The instrument now agrees with both critics,
  in the same direction: the fringe carries far more high-frequency contrast than
  delivered cloth does.
- `cloth_edge`, dead since D-138 fused the pillows away and took its only control with it:
  fires again on a control that exists in this frame (bed plinth on rug, 100%) —
  **0.893x vs cut ≥0.5, CASTS A LINE (pass)**.

## 6. ADDENDUM — THE SAME DEFECT A FOURTH TIME, IN P4's SCORED ROW

Written while preparing the plan review, because it would have been careless to file
verdicts on P4 without checking whether ITS row reads the room. **D7 — "loose styling
objects in the camera frustum" — was printing 0.**

The scene dump has **193 objects in frustum, 0 occluded**, and `item_convention.item_id`
returned `None` for every one of them. Diagnosed:

- `place_model` names a bought styling object **`deco_<stem>__acq<N>`** — one underscore
  after `deco`, because the double underscore is the item/part separator. The convention
  tests `name.startswith("deco__")`.
- So `deco_books__acq0`, `deco_books__acq1` and `deco_bedthrow__acq0` — **all three in
  frustum** — matched no rule, matched no exclusion, and fell off the end of the function
  to a bare `return None`, **indistinguishable from a deliberate exclusion.**
- The module's own header says *"a 0 from a reader that cannot see is not a 0"*. It said
  that about an **old dump schema** and never about an **unrecognised name**.

**Fixed:** `classify()` returns `(id, verdict)` where verdict is `item` / `excluded` /
**`unknown`**; `count_items` returns the in-frustum names it could not classify either
way, **in the return value rather than in a helper** — a channel the caller must remember
to read is a queue whose consumer never visits it; `deliverable_check` prints them beside
the count.

**The honest reading on the frame of record: D7 = 2, not 0** (`bedthrow`, `books`) against
a required 12, **plus 51 in-frustum names the convention cannot classify either way**,
now printed. The verdict does not move — D7 was already FAIL and the frame still
QUALIFIES on 5/6 mandatory rows — but the number P4 is steered by was wrong, and the
direction it was wrong in was *flattering to nobody and legible to no one*: it made a
sparsely-styled room look like an empty one, so no round could tell progress from noise.

**ONE SMALL THING FIXED ON THE WAY, because it is the same shape:** `PE.run` writes every
crop it takes into the project's stage dir, so a test that exercises the harness dirties
the working tree — `p2-exit-crops/probe/` is exactly that, left by an earlier test and
