## 1. WHAT WAS BUILT

`pipeline/scripts/model_assert_check.py` (pure, no `bpy`), wired into
`rule_gate.check` (reproduction lane) **and** `rule_gate.check_room` (this lane,
called by `build_room` before a single vertex is made).

**Discovery is not an allowlist** — R9b's law applied to model references. Two
independent detectors, union is the scope:

- **key shape** — `model`, `*_model`, `*_models`, never `*_note`; the flag
  propagates down the whole subtree (a test caught the version that reset it per
  level: `bed_models` holds `{"cloth_set": …}`, so the slug was only ever found
  by the other detector — i.e. only while the file existed. Delete the asset and
  the reference silently left scope, which is the failure this module is about).
- **value shape** — any string anywhere in the spec that resolves to a model
  directory on either shelf, whatever its key is called.

**Every row is diffed three ways and all three must agree:** what the SPEC
asserts ↔ what the file's own `.scale.json` SIDECAR recorded ↔ **a live
re-measure of the file, right now**. Plus: sidecar must be about this file
(basename match), class/axis must match, `ok` must be true, the band must still
be the band in force, the primitive count must match, and an unknown class fails
closed. **COULD NOT MEASURE is its own violation**, never a pass (R11).

**An orphan row is refused by name.** That is the p2r36 shape made structurally
impossible: `2b142a32`'s numbers cannot sit in the file describing `ub806591a`,
because nothing points at `2b142a32`.

**One line per model reference prints on every run** — the closing condition, and
it is a condition rather than a nicety: the number that was wrong for two rounds
was wrong in a place nobody printed. (`debt_check` had the identical bug: its
tally went into `note()` detail, which only prints for SKIPPED rungs, while its
own comment claimed it printed in the render path.)

## 3. THE HALF A BAND CANNOT ANSWER, AND THE METRIC THAT PREFERRED THE WRONG ASSET

`asset_scale` answers *is the UNIT right* and says so in its own docstring. It
cannot answer *is this the right SIZE for the job* — `ub806591a` is honestly
1599.9 mm and honestly inside the `bedding_set` band, and it still cannot dress
this bed. So `model_requirements` carries a **declared-only** `covers` clause:
the plan the model must cover, **derived** from the spec item it dresses (R9 —
`{"item": 1, "inset_mm": 90}` reads the bed's own w/d, so re-drawing the bed
re-aims the requirement and no second copy of its size exists to drift).

**p2r36's NEXT #2 — re-audition the 22 cached candidates — is DONE, by pure
measurement, with no render.** The result is not the one the round expected:

| p2r31 audition | coverage | relief | falls past | size filter |
|---|---|---|---|---|
| **`ub806591a` — THE ONE CHOSEN** | 90.3% | 20 mm | 2/4 | **REFUSED, 1.231×** |
| `8635b5b9` | 80.8% | 138 mm | 1/4 | passes at 0.845 |
| `2b142a32` | 60.0% | 104 mm | 0/4 | passes at 0.828 |
| `ub4631bf5` | 66.8% | 88 mm | 1/4 | passes at 0.939 |
| `22897dd4` | 60.7% | 107 mm | 1/4 | passes at 0.637 |

**Of the five auditioned, the one that was picked is the only one the filter
refuses. The other four all pass.** The reason is visible in p2r31's own table:
the deciding metric was COVERAGE, and coverage is maximised by a cloth that lies
flat ON the mattress without reaching past it — a duvet too small to drape scores
best. The number that answers the real question was printed in the same row and
read past: **falls past 2 of 4 sides.**

That is this repo's recurring shape — *a metric that cannot separate two things*
— and it is worse than a missing metric, because it actively ranked the failure
first. Filed as a lesson, not as a defect in p2r31's honesty: the table is
complete, and the complete table is what makes this diagnosable today.

**Not decided here and not to be read as decided:** which candidate dresses this
bed best. That needs the eye and a frame. What is now impossible is auditioning
one that cannot fit, and it costs no render to know.

## 4. TWO HOLES CLOSED THAT NOBODY HAD NAMED

**(a) THE WHOLE COMMITTED CC0 SHELF WAS UNASSERTED — 13 of 13.** `warehouse.py`
wrote a `.scale.json` on every fetch; `assets.py` (Poly Haven) had no such line,
and `pipeline/CLAUDE.md` carries the assertion as a MUST. So the rule read as
enforced everywhere it was mentioned while half the shelf had never been checked,
and `_model_path` handed those files straight to `place_model`. Fixed at the
source: the writer moved into `asset_scale.write_sidecar`, both fetchers call it,
`asset_scale.py --sidecar` re-asserts anything already cached. 12 of 13 now
asserted (three new bands — sofa / coffee_table / ottoman — each cited, each
deliberately WIDER than the ergonomic range it cites, because the shelf holds a
real 491 mm table and a real 624 mm ottoman and refusing those would be the band
judging taste).

**`calathea_orbifolia_01` is deliberately NOT asserted, and the reason is a
finding:** the file is **five variant plants laid out side by side** (nodes
`_a`…`_e` at x −1 / 0 / +1), so its 2492 × 1194 mm bounds describe a LAYOUT, not
an object, and no single-object band can be true of it. The existing code comment
called it "a floor plant" — right about the outcome (it is refused, procedural
pot and foliage carry the styling), wrong about the mechanism. One calathea is
~601 × 525 × 424 mm and would be usable if the variants were split: filed, not
done.

**(b) THE DOOR NOW ASSERTS.** `build_room._model_path` is the one function every
consumed mesh comes through. It refuses any slug whose sidecar does not assert a
unit, prints why, and returns `None` so each caller takes its own loud fallback.
Previously the rule was spread across call sites and only two of them
(`_place_bed_cloth`, `_place_pillow_combo`) actually read a sidecar — the item
loop, the decor lane and every `MODEL_MAP` default did not. **A rule spread
across the callers is a rule with one exemption per caller.**

Two rules, each universal inside its own domain: **the GATE governs what the spec
NAMES, the DOOR governs what the build LOADS.**

**And the flag that went round both:** `--bed-cloth-set=<slug>` set a module
global, so a CLI-named asset rendered with no assertion, no sidecar diff and no
size check — a hole straight through the rung built to close p2r36, in the very
lane it was built for. It now writes into the spec before the gate runs (the law
`--item-model` already followed). Auditions of unasserted candidates belong in
`bedcloth_shoot` / `bedcloth_bench`, which import directly and are measurement
tools; the deliverable build renders what the spec can account for.
