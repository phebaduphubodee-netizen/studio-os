# BlenderKit model study — ผ่าของที่ซื้อให้เป็นความรู้ก่อน sub หมด (2026-09-01)

คำสั่งพี่ verbatim (แชท 2026-09-01, สะกดตามจริง):
**"ผมมีไอเดียว่า การจะทำให้การซื้อ subscrition ได้ประโยชน์สูงสุดเดือนนี้ คือคุณข้องไปทำการศึกษา model ใต blenderkit เพื่อที่หลังจาก sub หมดคุณจะปั้นเองได้ และเข้าใจการออกแบบมากขึ้น"**
และตามมาอีกสองประโยคในชั่วโมงเดียวกัน ซึ่งขยาย scope จาก "ของบนเครื่อง" เป็น "ทั้งคลัง + ทุกวัน":
**"ไม่ใช่แค่ของที่อยู่ในเครื่องผมอยู่แล้ว วางแผนเรียนให้หมด"** · **"ผมจะสั่งให้คุณเรียนทุกวัน จนกว่าจะถึงวันหมด"**

**แก้จังหวะ 2026-09-02** — พี่ถาม *"เรียนได้แค่วันละเรื่องหรอ?"* แล้วสั่ง **"งั้นแก้แผนให้เรียนกี่เรื่องก็ได้ต่อวัน"**.
ความ "ทุกวัน" ยังอยู่ ที่ปลดคือ **จำนวนต่อวัน**. เหตุผลที่ตารางวันละหน่วยเป็นอันตรายไม่ใช่แค่ช้า:
มันมัด **ครึ่งที่หมดอายุ** (การดึงของที่ต้องจ่าย ตายพร้อมสิทธิ์ 2026-09-21) เข้ากับ **ครึ่งที่ไม่หมดอายุ**
(โน้ต + การตรวจฝ่ายค้าน ซึ่งรันจาก probe dump 1.3 MB ได้ตลอดไป) — ค่าสมาชิกจึงถูกใช้ด้วยความเร็วของการเขียนโน้ต
และหน่วยที่ต้องจ่ายหน่วยสุดท้ายถูกวางไว้บนวันหมดอายุพอดีโดยไม่มีวันสำรอง. หลักสูตรจึงเปลี่ยนจาก
**ปฏิทิน** เป็น **คิวที่มีลำดับ**: `order` = ลำดับ (ไม่ใช่วันที่), `suggested_date` = บันทึกของแผนเดิมเท่านั้น,
`deadline` มีจริงเฉพาะหน่วยที่ต้องจ่าย. และเส้นที่ **ล้มได้** คือ BURN RATE ที่ `study_curriculum.py` พิมพ์ทุก session:
หน่วยที่ต้องจ่ายและยังไม่ปิด เทียบกับวันที่เหลือ — แดงเมื่อวิ่งไม่ทัน (มี negative control ใน test).
เพดานดิสก์ 1 GB/วันก็ยกเลิก: วัด 2026-09-02 เหลือที่ว่าง 141 GB และของที่เหลือทั้งหมด ~10 GB.

## ทำไมนี่คือช่องที่แผนเดือนยังไม่มี

`docs/blenderkit-month-2026-08-22.md` (D-119) ตอบคำถามเดียว: *ของซื้อทำให้เฟรมดีขึ้นไหม* —
ทุกเกณฑ์ของมันมองที่ผลลัพธ์ (bench, panel, คู่ภาพ A/B) ไม่มีบรรทัดไหนอ่านว่า**ข้างในไฟล์
สร้างยังไง**. สิ่งที่หมดอายุวัน 30 คือ*สิทธิ์ดาวน์โหลด* ไม่ใช่*ไฟล์ที่โหลดแล้ว* — .blend 71 ไฟล์
บน shelf อ่านได้ตลอดไป แต่บทเรียนในนั้นยังไม่เคยถูกอ่านออกมาเลย.

และ bottleneck ที่มันตอบคือตัวที่ harness audit (2026-08-31, commit 2870bd6) เพิ่งวัดได้:
รอบปั้นชน R1 stop-loss สองรอบทั้งที่ massing คลาด <2% — **คอขวดคือ vocabulary ของ kernel
ไม่ใช่ตาโมเดล**. ของซื้อ 71 ตัวคือคลังคำตอบว่ามืออาชีพเขียน vocabulary นั้นยังไง อยู่บนดิสก์แล้ว.

## วิธี — สามชั้น อ่านโครงสร้างจริง ไม่ใช่ความรู้สึก

1. **PROBE** — `pipeline/scripts/model_study_probe.py` เปิดทุก `.blend` แบบ headless
   (`--factory-startup -Y`, ไฟล์ third-party, อ่านอย่างเดียวไม่เซฟ) แล้ว dump ต่อ asset:
   topology (verts/tri/quad/ngon, verts/m², smooth share), modifier stack พร้อมค่าที่ถือ idiom
   (SUBSURF levels, BEVEL width/segments, DISPLACE strength), shape keys, curve bevel,
   node tree ของทุก material (histogram + ตามสายว่าอะไรป้อน Principled input ไหน),
   ทุก image (ขนาด/colorspace/บทบาท) → `assets/shared/blenderkit/_study/<id>.probe.json`.
2. **ANALYZE** — agent ต่อกลุ่มคลาส เทียบ dump กับ**โค้ดของเราที่พยายามสร้างคลาสเดียวกัน**
   (build_room.py, millwork.py, material_presets.py, drape.py) แล้วเขียนโน้ตกลั่นลง
   `knowledge/_inbox/model-study/` — ทุกข้อเรียนต้องถือ**ตัวเลขจาก dump** ไม่ใช่คำคุณศัพท์.
3. **VERIFY + SYNTHESIZE** — verifier ไล่เช็คทุกตัวเลขในโน้ตกลับไปที่ dump (วินัย
   flattering-scorer: คนเขียนโน้ตห้ามเป็นกรรมการของตัวเอง) แล้วสังเคราะห์เป็น curriculum
   จัดลำดับตามคลาสที่เราล้มจริงในเลน (ผ้าพับ/duvet, เสื้อผ้าแขวน P2r-20, พรม
   ORD-2026-08-25b, R8 free-form) — บอกว่า kernel ของเราขาดคำไหน และคำนั้นสะกดยังไง.

## ตัวอย่างแรกที่พิสูจน์วิธี (asset 03ede500, เสื้อเชิ้ตบนไม้แขวน, full-plan)

- เสื้อ = **quad cage 2,332 verts + SUBSURF** — ~1,600 verts/m² เท่านั้น (เราเคยเข้าใจว่า
  ผ้าจริงต้อง sim หนา ๆ; ของจริงคือ cage บาง + subdivision)

- ไม้แขวน = plywood PBR ครบสามแผ่น (diff/rough/normal 2K packed) บน 538-vert cage

## "เสร็จ" ไม่ใช่ประโยคของผู้เรียน (เพิ่ม 2026-09-01 หลังพี่พูดตรง ๆ)

พี่: **"สิ่งที่ผมกลัวคือคุณชอบข้ามงานในงาน (สรุปว่าเสร็จแล้ว เรียนเสร็จแล้ว ทำได้แล้ว แต่พอผมเป็นเช็คก็เจอว่ามันห่วย)"**
— และ repo วัดมาแล้วว่าเขาถูก: builder จับ defect ตัวเองได้ 30-50% (R3), ตา builder เป็นกรรมการได้ 0 conviction
จาก 367 ข้อ (R7d), และ gate เคยเขียน "มีลิ้นชัก+มือจับ" บนพิกเซลที่ไม่มีทั้งสองอย่าง (process debate 08-25).

คำตอบเชิงระบบ (อยู่ในโค้ด ไม่ใช่คำสัญญา — `study_curriculum.check()` ปฏิเสธโดยชื่อ, negative control
พิสูจน์แล้วว่าจับได้ครบสี่รูปแบบ):
1. ทุกหน่วยมี **exam ที่ pre-register ก่อนเรียน** (เฉลยล็อกก่อนวัด — บทเรียน harness audit)
2. หน่วย done ต้องมี **exam_evidence** (path/เลขที่ชี้กลับได้) และ **judged_by ที่ไม่ใช่ builder** —
   โน้ตใช้ verifier-agent ฝ่ายค้าน, รั้วเครื่องใช้ instrument, **practice rep (วัน 25-27) ปิดได้เฉพาะ c2/c3/owner**
3. สถานะซื่อสัตย์ของหน่วยโน้ตคือ *notes-verified* ("ตัวเลขไม่โกหก") — **ไม่ใช่ "เรียนแล้ว"**;
   "ปั้นเองได้" ประกาศได้เฉพาะเมื่อ rep ทั้งสามผ่านกรรมการตาบอด และเฟรมเลนเลิกโดน critic ยื่นในคลาสนั้น
4. คำสุดท้ายเป็นของพี่ อ่านจาก render (R3) — รายงานปิดวัน 30 ต้องเขียนสถานะ rep ตามคำตัดสินกรรมการตรง ๆ รวมกรณีตก

## ขอบเขตที่ประกาศไว้ก่อน (จะได้ไม่อ่านผิดตอนจบ)

- ชั้นนี้อ่าน**โครงสร้าง** ไม่ใช่พิกเซล — ครึ่งพิกเซล (GLB vs native render) เป็นบรรทัด R4
  ของ D-119 อยู่แล้ว ไม่ทำซ้ำที่นี่. R11 ยังจริง: โครงสร้างที่อ่านได้ ≠ สวยแล้ว —
  ทุกกฎที่กลั่นออกมาต้องไปพิสูจน์ในรอบ build จริงของเลนก่อนถือเป็นความรู้ LIVE.
- การศึกษา**ไม่แตะโปรโตคอล C2 ของ D-119**: ห้าคลาสที่ยังไม่มี free baseline
  (wall_art, plant, cushion_throw, nightstand_objects, hung_garments) ยังห้าม paid fetch
  จนกว่า baseline จะรัน — การอ่านไฟล์ที่ซื้อมาแล้วไม่ปนเปื้อนอะไร แต่การซื้อเพิ่มต้องเดินตามลำดับเดิม.
- โน้ตทุกใบเป็น REFERENCE tier ใน `_inbox/` จนกว่าจะถูกกลั่นเข้า `knowledge/` ตาม flow ปกติ.
- ก่อนวัน 30: ถ้า synthesis ชี้ว่าคลาสไหนควรมี "ตัวเรียนเพิ่ม" (เช่น เตียงที่ผ้าจัดแล้ว,
  ผ้าม่านสำเร็จ) ให้ยิง study-fetch ในคลาสที่**ไม่อยู่**ในห้าคลาสข้างบน — ของฟรีโหลดได้ตลอด
  ไม่ต้องรีบ, ของ full-plan หมดสิทธิ์ ~09-21.
