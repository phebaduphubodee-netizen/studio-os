## 2. TOP-10 กฎ transferable — เรียงตาม defect ของเลนที่มันรับใช้

1. **[ASK-002/duvet] ผ้าเตียงที่ขายได้ = geometry อบแล้วที่ pitch 3–6มม. (25.2k–120.9k v/m²) — ไม่ใช่ sim สดบน grid หยาบ.** เรา: duvet cell 0.042 → 570 v/m² = pitch 42มม. = หยาบกว่า 7–14× เชิงเส้น (`build_room.py:10242`); ไม่มี shape key เลยใน 100 meshes ของ pro = bake ครั้งเดียวแล้ว freeze. → โน้ต bed (idiom 1, delta 1)
2. **[ASK-002/duvet] แต่งเตียงเป็นชั้นด้วยเลขวางผ้า:** quilt คลุม 67–90% ของความยาว + ห้อยข้างเกินชั้นใต้ 105–148มม./ข้าง + drape surplus 2.5–3.4x ของ plan bbox (donor เรา 1.94x = คำอธิบายเชิงเลขว่าทำไมเตียงแบน) + หมอนแยกใบ mesh ไม่ซ้ำ rot=0 (เอียงได้สูงสุด 1 ใบ/เตียง) + bolster เป็น vocabulary. → โน้ต bed (idiom 2-3, 5-6)
3. **[ทุกคลาส acquire — คมสุดที่ ORD-2026-08-25b + P2r-20] อย่าให้ท่อ GLB ฆ่าของที่ซื้อ:** 19/39 material กลุ่ม organic มี node ที่ glTF ไม่มีที่อยู่ (พิสูจน์ในซีน: แก้ว→โครเมียม Metallic 1.0, ใบ ficus เสีย TRANSLUCENT, logo น้ำหอมดำ) และ `export_apply=True` อบ SUBSURF ที่ viewport L1 = 1/4 ความละเอียดที่จ่ายเงิน — คำตัดสิน p2r86 "การ์ดพับ" ก็ทำบนร่าง glb (5,200 quads→0). hero asset เข้าซีนจาก `.orig.blend` หรือ rebuild shader + แก้ `blenderkit.py:215` levels=render_levels. → โน้ต organic (Δ1-Δ2), garment (D2-D3), props (delta 4)
4. **[ORD-2026-08-25b พรม] พรมแบนเพราะ ingest ไม่ใช่ vendor:** `rug__acq0` เหลือ node 2 จาก 15 — หาย AO+HUE_SAT+BUMP×2+DISPLACEMENT(scale 0.5)+ภาพ 1/3 ทั้งใบ และ height map ถูกเสียบเป็น normal map (คนละความหมายเชิงเรขาคณิต). ซ่อม ingest ก่อนตัดสินเรื่องสวย; `0fd746ae` vs `_ours` = negative control สำเร็จรูป. → โน้ต materials (delta 1, กฎ 1)
5. **[P2r-20+P2r-31] ไม้แขวน = MESH ไม้หนา 16.5–38.1มม. งบแค่ 366–760 verts (pro 12/12, CURVE=0)** — ของเราคือ CURVE ลวด ⌀3.6มม. ×23 เส้น ที่บางกว่าไม้จริง 4.6× และล่องหนต่อทุก rung ที่อ่านแต่ MESH. แก้ `build_room.py:6288`; ราว→บ่า derive จาก hook จริง ≈113มม. ไม่ใช่ `_HANG_RESERVE=0.150` พิมพ์มือ. → โน้ต garment (กฎ 1, 6)
6. **[ORD-2026-08-26 ของในตู้] ผ้าพับปั้นเอง = กรง all-quad 1.1–4.3k quads + SUBSURF CC level 2 + ผนังคู่จากการพับแผ่นจริง** (area/footprint 8–11; SOLIDIFY 0/10; slab ผิวเดียวของ `folded_knit` เรา ~2 ไม่มีทางให้ชั้นผ้า/ปากผ้าโผล่). เพดานพิสูจน์แล้ว: b89bc1af 1,354 verts + procedural ล้วน = full_plan quality. → โน้ต folded (กฎ 1-2, idiom 9)
7. **[ORD-2026-08-26 + HOLE-01] grammar กอง/วาง: ความเป็นธรรมชาติมาจากการจม+เลื่อน ไม่ใช่การหมุน.** กองผ้า: ชิ้นบนจม 35–38% ของความหนาชิ้นล่าง (z-pitch 0.62–0.65×h), jitter XY ≤±8มม., กว้างแกว่ง ±7% ไม่-monotonic, rot=0 ทุกชิ้น; กองหนังสือ: จม −0.3มม., เลื่อนสลับข้าง ≤6มม., rot_z เท่ากันทุกเล่ม, เล่มหนาสุดอยู่บน; เฉพาะเล่มบาง ≤12มม. เอียง 6–18° ปลายแถว. `folded_stack` เราวางชน+taper เส้นตรง = tell ของบล็อก. → โน้ต folded (กฎ 3-4), props (กฎ 1-2)
8. **[P2r-5 ผิวผ้า] ผิวผ้ามี 3 ชั้นและแต่ละชั้นมีเลข:** ทิศเส้นด้ายจาก mapping ยืดแกนเดียว ~5× ([2,11,2]) หรือ TEX_MAGIC — 512px มีทิศชนะ 4K ไร้ทิศ; sheen ไล่ตามชนิดผ้า 0.02–0.3 ฐาน 0.2 (caller เราส่ง 0.5–1.0 ชน `_SHEEN_CAP=0.4` = ทุก textile แบนเท่ากันที่เพดานเกิน band pro); displacement จริง 0.1–1.5มม. บนผ้า (เรามี ShaderNodeDisplacement = 0 ทั้ง repo); ริ้วกลางของผ้าเตียง = image height map (SheetWrinkles class) ซ้อนเป็น BUMP. → โน้ต materials (กฎ 2-4), bed (กฎ 5-6), garment (กฎ 4)
9. **[P2r-29 sense list] อย่าโมเดลสายไฟ — โมเดลกลไก:** pro 0/4 มีสายไฟ แต่ใส่ pull-chain ⌀3.2×140มม./harp/หลอดเป็นวัตถุ/ปุ่ม-สกรู 3.2–15.4มม. (ช่วงหลัง verifier รอบสอง); มือจับบานตู้ = ~200 verts แกะใน mesh บาน + material slot โลหะ (ไม่ใช่ object แยก ไม่ยื่นพ้นบาน); เงาเป็นนโยบายของ material ไม่ใช่ object (`visible_shadow=False` เหมาทั้งโคม `build_room.py:12694` ทำฐานลอย — pro ให้ฐานทิ้งเงาเต็ม เฉพาะกระจกหลอดใช้ LIGHT_PATH). → โน้ต lamp (กฎ 1-3), casegoods (กฎ 4)
10. **[P2r-2 ลายไม้] casegoods มีสูตรวัสดุเดียว: per-object UV bake trio (BaseColor sRGB + Rough map + Normal map @2048, mapping_scale=1.0, Metallic/Sheen/Disp=0, roughness ห้ามเป็นค่าคงที่)** — ซีนเรา mill ไม่มี UV 188 mesh + 23 CURVE จาก 284 objects (แก้จาก 211/284 หลัง verifier รอบสอง — CURVE ต้องนับแยกเพราะ unwrap คนละทาง) จึงตกไปใช้ BUMP จาก Diffuse luminance; ประตูของทั้ง stack คือ unwrap ก่อน (cube project พอ) แล้วต่อ nor_gl 2k ที่แคชอยู่แล้ว. งบ mesh nightstand ทั้งใบ ~300–820 verts (ตัวอย่างจริงบนสุดของคลาสคือ 820 — band เดิม 300–800 เขียนแคบกว่าหลักฐานตัวเอง, verifier รอบสองจับ). → โน้ต casegoods (กฎ 5-6)

## 5. จุดที่โน้ตขัดกันเอง — ตัดสินด้วยการเปิด dump (ไม่เฉลี่ยความเห็น)

1. **mapping ผ้า uniform หรือยืดแกนเดียว?** โน้ต bed (delta 3): "pro ผ้า uniform ทั้ง corpus" vs โน้ต garment/materials: idiom คือ [2,11,2] ยืด 5.5:1.
   **เปิด dump:** `8968de2e` ทุก mapping_scale x=y จริง (42/3.9/7/5/5/3) แต่ `03ede500` มี **[2.0, 11.0, 2.0]** จริง.
   **คำตัดสิน:** uniform เป็นกฎของ **ผ้า image-based คลาส whole_bed เท่านั้น** — ประโยค "ทั้ง corpus" ของโน้ต bed ผิด (over-generalize จากคลาสตัวเอง). ผ้า procedural ของ garment ยืดแกนเดียวเป็น idiom ทิศด้าย. ผู้ใช้กฎ: duvet → uniform+image; `_woven` → ต้องมี aniso.
2. **bump ผ้าต้องเป็น image เสมอ?** โน้ต bed (กฎ 6): "Bump/normal ผ้าต้องเป็น image" vs โน้ต folded/garment: `BUMP<PROC:NOISE>` เป็นทางปกติ.
   **เปิด dump:** `8968de2e` grep PROC = **0 node** (image ล้วนทั้ง asset); `b89bc1af` Normal = **`BUMP<PROC:NOISE>` ทั้ง 2 material**.
   **คำตัดสิน:** กฎ image เป็นกฎ**คลาส whole_bed** (ผ้าผืนใหญ่ hero ระยะใกล้) ไม่ใช่กฎ corpus — throw/garment ใช้ procedural bump แล้วตลาดรับ. generator วัน 26/27 เลือกตามคลาส ห้ามยกกฎ bed ทาทุกผ้า.
3. **เพดาน sheen คือ 0.2 หรือ 0.3?** โน้ต bed: "อย่าเกิน 0.3" vs โน้ต folded: "0.2 คือเพดานที่คลาสนี้ใช้จริง" vs โน้ต materials: "ลด `_SHEEN_CAP` → 0.3".
   **เปิด dump:** `8968de2e` มี `"Sheen Weight": 0.3` จริง; `0cb10427` = 0.0, `f601337c` = 0.0, `b89bc1af` = 0.2.
   **คำตัดสิน:** ไม่ใช่เลขเดียว — เป็น**บันไดต่อคลาส**: whole_bed 0–0.3 (ฐาน 0.2) · throw_folded 0–0.2 (default 0) · garment 0.2. `_SHEEN_CAP=0.3` ใช้เป็นเพดาน global ได้ แต่การแก้จริงอยู่ที่ caller (ที่ส่ง 0.5–1.0 อยู่ตอนนี้) ต้องส่งค่าตามชนิดผ้า ไม่ใช่พึ่ง clamp.
4. **มือจับ/ปุ่มเป็น object แยกหรือแกะใน mesh?** โน้ต casegoods (กฎ 4): "มือจับ = geometry ในบาน ไม่ใช่ object แยก" vs โน้ต lamp: "ปุ่มไขลาน/สกรูเป็น object แยกพร้อม SUBSURF".
   **เปิด dump:** `24c65eb4` objects = root+legs+Body+Door เท่านั้น — `Handle` เป็น **material slot** ไม่ใช่ object; `94bf975c` = **~25 mesh แยก** (กระบอก/ทรงกลม/ปุ่ม/สกรู ระดับ 3–15มม.).
   **คำตัดสิน:** ถูกทั้งคู่ในคลาสตัวเอง — เส้นแบ่งคือ**ชิ้นที่ขยับได้ของกลไก** (ปุ่มหมุน คันโยก สกรู กระดิ่ง) = object แยก mm-scale, ส่วน**มือจับบานเฟอร์นิเจอร์** = แกะใน mesh บาน + slot โลหะ. sense-item "ตู้ไม่มีมือจับ" กับ "สวิตช์ไม่มีปุ่ม" จึงแก้คนละวิธี — ห้ามใช้สูตรเดียว.

## 6. ช่องที่ยังไม่ครอบ (บันทึกตาม exam ของหน่วย)

- **บนเครื่องไม่มีเลย:** curtains (คลัง 89% paid — วัน 12 คือโอกาสเดียว), upholstered seating, wall art, cushion/throw-pillow โซฟา, HDRI — โน้ตวันนี้พูดถึงคลาสเหล่านี้ไม่ได้เพราะไม่มี dump.
- **n เล็กจนสรุปเป็น corpus ไม่ได้:** rug (1), headboard (1), handbag (2), potted_plant (2), hanger (2) — กฎจากคลาสเหล่านี้เป็น hypothesis ที่ต้องเติมตัวอย่างในวัน 14/22 ก่อน generalize.
- **dump ตอบไม่ได้โดยสร้าง:** ทุกโน้ตมีหัวข้อ "คำถามที่ต้องพิสูจน์ด้วยพิกเซล" — รวม ~35 ข้อ ที่ต้องรอรอบ build จริงของเลน (R11: โครงสร้างอ่านได้ ≠ สวยแล้ว) และบางข้อรอเปิด `.orig.blend` วัน port (ramp stops ของ Recipe A/B, bevel_depth กำกวมของ Cloudrest).
- **โน้ตทั้ง 9 ใบผ่าน verifier ฝ่ายค้านแล้ว** (วัน 10 แปดใบ, วัน 11 หนึ่งใบ) — เหลือขั้น distill เข้า `knowledge/` วัน 29.
- **บทเรียนจากวัน 11 เรื่องตัวการตรวจเอง**: รอบตรวจ **รอบที่สองจับได้ 28 ข้อ ซึ่งเกือบทั้งหมดเป็นความขัดกันที่การแก้รอบแรกสร้างขึ้นเอง** (ย้ายขอบคลาสในที่หนึ่งแล้วลืมสถิติที่อ้างคลาสเดียวกันในอีกสี่ที่). ตรวจรอบเดียวแล้วแก้ = สร้าง defect ใหม่โดยไม่มีใครดู — โน้ตวันหลังต้องวนจนกว่าจะแห้ง (73 → 33 → 12 → …) ไม่ใช่ตรวจครั้งเดียว.
