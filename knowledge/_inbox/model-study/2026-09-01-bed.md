## idiom ที่พบ (ตัวเลข)

1. **ผ้าคือ geometry อบมาแล้ว ที่ vertex pitch 3–6 มม.** — ผ้าชิ้นหลักทุก asset 103k–728k verts, ความหนาแน่น 25.2k–120.9k v/m2 = pitch 2.9–6.3 มม. (stats median 28,651 = pitch 5.9มม.) และ**ไม่มี shape key เลยแม้แต่ mesh เดียวใน 100 meshes** (sk=[] ทั้งหมด) ยืนยันสมมติฐาน "bake มาแล้ว" ของ stats. สองสำนัก: สาย tri-ล้วน (Cloudrest/Slate/Obsidian — export จาก sim ภายนอก) กับสาย quad+SUBSURF (Bolzan/Loca — cage ชิ้นเล็ก 31–66k, ชิ้นหลักหนาแน่นอยู่แล้ว 103k–559k เช่น shawl Bolzan 559k, แล้ว subdivide ทับ) แต่จบที่ความละเอียดผิวเท่ากัน.
2. **เตียงจัดแล้ว = 2–4 object ผ้า + หมอนแยกใบ**: fitted/sheet ชั้นล่าง + quilt/duvet + blanket/throw พับปลายเตียง + (บ่อยครั้ง) shawl. หมอนแยกใบใน 6/10, ใบละ mesh **ไม่ instance** (`mesh_users=1` ทุกใบ; Slate `Pillow` 476×217 18,807v vs `Pillow.001` 497×255 21,120v — คลาสเดียวกันแต่ sim คนละครั้ง). bolster ทรงกระบอก (ชื่อ Cylinder ชัด) 3/10 (798–1688 มม.); Cloudrest มีใบยาว 1438 ที่อาจเป็นคลาสเดียวกันแต่ dump ตัดสินรูปตัดไม่ได้.
3. **หมอนแทบไม่หมุน**: rot_deg = 0 เกือบทุกใบ — เอียงจริงมีใบเดียวทั้ง corpus (93862856 `pillow 03` rot=(99.9,−1.1,−1.6) ≈ เอียง ~10° หลัง convention 90°). ความ "ธรรมชาติ" มาจาก mesh ที่ต่างกันใบต่อใบ ไม่ใช่จากการสุ่มหมุน.
4. **ตะเข็บ/รอยเย็บเป็น object แยกใน 5/10** (Cloudrest/Slate/Loca×2/Obsidian — ตรงตารางข้างบน): CURVE bevel เล็ก (Obsidian bevel_depth 0.001; Cloudrest 0.361/0.163 — หน่วยราคาสเกล object, ยังกำกวม) หรือ mesh ribbon จิ๋ว (Slate Seams0-6 พื้นที่ 0.0007–0.0027 m2, v/m2 ทะลุ 0.46–1.1M) — quilting/piping อยู่ใน geometry ชั้นบนสุด ไม่ใช่ใน texture.
5. **Drape surplus ของ quilt = 2.5–3.4x ของ plan bbox** (slab ปิดแบนได้ ~2.0–2.1): Ikea Blanket 10.18/3.04=**3.35x**, Cloudrest 3.22x, Slate 3.22x, Bed004 2.85x, Obsidian 2.54x — ส่วนเกินคือเนื้อ fold. ตัวที่แบนสุดคือ donor เราเอง (Metropol Blanket **1.94x** ≈ ไม่มี fold surplus).
6. **การวางผ้าคลุม**: quilt กินความยาวเตียง 67–90% — สองสำนัก: เว้นหัวเตียงลึก (Ikea Blanket 1349/2013 = 67%; Metropol 1358/1980 = 69%; Slate Quilt 1527/1895 = 81%) กับคลุมเกือบเต็ม (Cloudrest 1979/2217 = 89% ของ base; Obsidian 1960/2179 = 90%) — และกว้าง**เกิน**ชั้นใต้ ~105–148 มม./ข้าง (รวมสองข้าง 211–295: Ikea 2252 บน 1957 = +295 รวม/147 ต่อข้าง; Slate 144/ข้าง; Metropol 113/ข้าง; Cloudrest 105/ข้าง); Slate มี `Sheet` 1625×610 = แถบ turn-down หัวเตียงเป็น object ตัวเอง.
7. **Material ผ้าเตียง**: Sheen Weight ตั้งจริง 59.3% (35/59; อีก 22 = 0.0, อีก 2 ไม่ใช่ Principled) — ค่าที่พบ: 0.0015(Bolzan×6), 0.02–0.0303, 0.0744(scuba_suede×2), 0.08(velvet×2), 0.0937–0.0986, 0.1513(×6), 0.1565, **0.2 (โหมด, ×10)**, 0.2448, **0.3 (max, ×2: Cotton, waffle_pique)**. Roughness = image map หรือค่าคงที่ 0.8–1.0 (ไม่มี**ผืนผ้า**ต่ำกว่า 0.7; material `Seams` ของเส้นตะเข็บ Cloudrest = 0.5). **Normal ของผ้าเตียงมาจาก image เกือบทั้งหมด** — BUMP<IMG height> หรือ NORMALMAP<IMG nor_gl>; ข้อยกเว้นที่ dump ชี้: `black pillow` (93862856) = BUMP<GROUP> (มองใน group ไม่เห็น) และ `Tela Textura` (Tierra) ไม่มี bump chain เลย; ที่ยืนยันได้จริงคือ**ไม่มีผ้าชิ้นไหนใช้ PROC noise เป็น bump**.
8. **ริ้วผ้าระดับกลางมาจาก texture เฉพาะทาง**: Ikea ซ้อน `TCom_Fabric_SheetWrinkles01_0.54x0.54_2K_height.tif` เป็น BUMP ทับ cotton ทั้งบน Bedsheets และ Blanket — fold ใหญ่อยู่ใน geometry, ริ้ว 10–500 มม. อยู่ใน height map, weave อยู่ใน normal/rough ของผ้า. mapping_scale ผ้ากระจาย 0.2–42x (คลัสเตอร์ใหญ่ 1–15x; สุดโต่ง gingham 42x, ต่ำสุด Tierra Brown fabric 0.2), เกือบทั้งหมด **uniform x=y** (aniso แย่สุดทั้ง corpus = curly_teddy 0.84:1).
9. **Displacement ต่อสายจริง 42.4%** ของ material คลาสนี้ (ชุด 8-map สไตล์ AmbientCG ครบ anisotropy/spec_ior); ภาพ median 2048px, pack ในไฟล์ทั้งหมด.
10. **Tierra = ตัวเตือน D-120**: เตียงทั้งหลัง fused เป็น mesh เดียว 655,485v แต่แยก 6 materials (Dark fabric/Wood/Velvet×2/Brown fabric/Tela) — ระดับมืออาชีพก็ ship แบบ fused; เครื่องแยกส่วนต้องอ่านที่ **material ไม่ใช่ mesh**.

## delta vs โค้ดเรา (file:line)

1. **ความหนาแน่น duvet ชั้นฟรี**: `pipeline/scripts/build_room.py:10242-10243` duvet เรียก `softgoods.folded_sheet(..., cell=0.042)` → ~570 v/m2 = pitch **42 มม.**; throw `build_room.py:10664` cell=0.022 → pitch 22 มม.; default `pipeline/scripts/softgoods.py:71,228` cell=0.028. Pro bake ที่ 25.2k–120.9k v/m2 = pitch **2.9–6.3 มม.** — หยาบกว่า **7–14 เท่าเชิงเส้น (~44–212x ต่อพื้นที่)**. fold-energy เรา 2.115x เป้า / throw 3.682x (พับถี่เกิน) วัดบน mesh ที่ pitch เดียวกับ fold ที่พยายามสร้าง — grid 42มม. บังคับ fold รัศมีต่ำสุด ~2 cell จึงได้ fold เหลี่ยมถี่แทน fold โค้งใหญ่.
2. **Sheen เกินเพดาน pro**: `build_room.py:2988` `_SHEEN_CAP = 0.4` และซีนจริง `bed_duvet`/`bed_mattress` Sheen=0.4 (จาก `_ours_p2r91`) — corpus นี้ **max = 0.3** และโหมด 0.2. คอมเมนต์ `build_room.py:2990` อ้างสถิติเก่า 102 materials {0.0:94, 0.2:1, 0.4:7} — ชุด BlenderKit เตียง 59 materials ให้ภาพต่าง: ตั้ง sheen มากกว่าครึ่ง แต่ไม่มีตัวไหนถึง 0.4.
3. **Bump ผ้าเราเป็น procedural**: ซีนเรา `bed_duvet` Normal=`BUMP<MIX_RGB<PROC:NOISE>>` ขณะ roughness มี IMG (`rough_linen_Rough_2k.jpg`) — pro ใช้ height/normal **image** ทุกชิ้น (idiom 7-8). `pipeline/scripts/material_presets.py:378-403` เขียนเองว่า "middle band missing" — dump ยืนยัน: ตัวที่ขาดคือ SheetWrinkles-class height map เป็น BUMP ไม่ใช่ noise เพิ่ม. อนึ่ง mapping_scale duvet เรา [2.857, 0.408, 2.857] (บีบแกน y 7:1) — pro ผ้า uniform ทั้ง corpus.

## กฎ transferable จัดอันดับ

1. **ผ้าเตียงที่ขายได้ = geometry ที่ pitch 3–6 มม. อบมาแล้ว, ไม่ใช่ sim สดที่ grid หยาบ** — เป้า ≥25k v/m2 บนชิ้นหลัก (pro 25.2k–120.9k; เรา 570). ทางที่งบถึง: sim/sculpt ละเอียดครั้งเดียวแล้ว freeze เป็น asset ภายใน (แบบเดียวกับที่ Bolzan ใช้ SUBSURF cage 30k → เรนเดอร์หนา).
2. **แต่งเตียงเป็นชั้น**: fitted-sheet เต็มผืน + quilt คลุม 67–90% ของความยาว (สำนักเว้นหัวเตียง 67–81 / สำนักคลุมเกือบเต็ม ~90) ห้อยข้างเกิน ~105–148 มม./ข้าง + throw/blanket พับปลายเตียง + แถบ turn-down เป็นชิ้นของตัวเอง — ตัวเลขวางผ้าอ่านจาก dims ได้ทันที ไม่ต้องเดา.
3. **หมอน: หลายใบ mesh ไม่ซ้ำ, rot=0** — ความต่างอยู่ในผิว (sim ต่อใบ) ไม่ใช่ transform; เอียงได้มากสุด 1 ใบ/เตียง; เพิ่ม bolster ทรงกระบอกเป็น vocabulary (พบชัด 3/10, ยาว 798–1688 มม.).
4. **fold แม็คโครต้องมีเนื้อผ้าให้พับ**: quilt ควรมี drape surplus (area/plan) **2.5–3.4x** — ต่ำกว่านั้นคือ slab; ใช้เป็น instrument ใหม่ได้ทันทีเพราะอ่านจาก dump ของเราเองได้เลข (donor Blanket 1.94x อธิบายว่าทำไมเตียงเราแบน).
5. **Sheen ผ้า 0.0015–0.3, โหมด 0.2 — อย่าเกิน 0.3**; roughness ผ้า ≥0.7 หรือใช้ map; ลด `_SHEEN_CAP` consumer ฝั่งเตียงให้อยู่ในแบนด์นี้.
6. **Bump/normal ผ้าต้องเป็น image** — ชั้นริ้วกลาง (SheetWrinkles height ~0.5×0.5 ม./tile) ซ้อนเป็น BUMP บนผ้าเรียบ; mapping uniform; นี่คือคำตอบเชิงเครื่องมือของ "middle band" ที่ material_presets.py ประกาศว่าขาด.
7. **ตะเข็บเป็น object**: curve bevel ~1 มม.ตามแนว quilt/หมอน (Obsidian 4 curve, Slate 7 ribbons) — ถูกกว่า displacement ทั้งผืน; ส่วน "อ่านออกเป็นของเย็บที่ระยะกล้องเรา" ยังเป็นคำถามพิกเซล (ดูหัวข้อท้ายไฟล์, LEGIBILITY P2r-29).
8. **เครื่องแยกส่วนเตียงต้องอ่าน material ไม่ใช่ mesh** — pro ship ทั้ง fused (Tierra 1 mesh/6 mat) และ merged-pillow-row (Ikea/Bed004) ; กฎ D-120 ที่วัดที่ mesh จะจับผิดทั้งสองแบบ.

## คำถามที่ต้องพิสูจน์ด้วยพิกเซล

- pitch 4–6 มม. ทำให้ fold-energy ในเฟรม (ตัววัด 2.115x ของเรา) ลงมาที่แบนด์เป้าจริงหรือไม่ — dump บอกได้แค่ความหนาแน่น ไม่บอกรูปคลื่น fold.
- drape surplus 2.5–3.4x แปลเป็น fold ที่ "อ่านออก" ที่ระยะกล้อง p2 หรือถูก occlude หมด (ตัวในเฟรมเพดาน 73% ของเรา).
- Sheen 0.2 vs 0.4 ต่างกันกี่ code บนผ้าใต้แสงซีนเรา (บทเรียนเดิม build_room.py:3938 บอก sheen lever ~1 code — ต้องวัดซ้ำบนผ้า image-bump).
- ตะเข็บ curve bevel 1 มม. มองเห็นจริงที่ resolution เรนเดอร์ของเราหรือเป็นงบ verts ทิ้ง (LEGIBILITY class P2r-29).
- SheetWrinkles height เป็น BUMP: amplitude เท่าไรจึงอ่านเป็นริ้วไม่ใช่ noise — ต้อง bracket ตามกฎ amplitude-bisect เดิม.
- bevel_depth 0.361 ของ Cloudrest คือหน่วยอะไรกันแน่ (สเกล object กำกวมใน dump) — ห้ามลอกตัวเลขนี้จนกว่าจะเปิดไฟล์จริง.
