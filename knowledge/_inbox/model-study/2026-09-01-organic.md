## idiom ที่พบ (ตัวเลข)

1. **cage เล็ก + SUBSURF ทิ้งไว้เป็น modifier (render_levels=2) — ไม่ bake.** ทุก vase
   ทั้ง 4 ตัว + slippers + laces: cage 48–2,304 v, render_levels=2 ทุกตัว; ส่วนใหญ่
   viewport=1 (ยกเว้น laces ×2 และ Water ที่ตั้ง viewport=2).
   เก็บถูก แก้ถูก และ silhouette ตอนเรนเดอร์ = 4× ของ cage.
2. **ของคู่ = สร้างข้างเดียว**: slippers ใช้ MIRROR modifier; leather shoe ใช้ object
   สองตัวแชร์ mesh เดียว (mesh_users=2, 17,944 v เก็บครั้งเดียว).
3. **ใบไม้ = alpha card + TRANSLUCENT ไม่ใช่ geometry ต่อใบ และไม่ใช่ instancing**:
   ficus canopy ทั้งพุ่ม 17,035 v (mesh_users=1); olive ทั้งต้น 83,826 v ใน mesh เดียว.
   มูลค่าที่ซื้ออยู่ใน photo atlas 22–29 ใบ ≤4K (สิ่งที่ R8 บอกว่าเราสร้างจากเลขที่วัดได้ไม่ได้).
4. **ตะเข็บหนังมี 2 สำนัก**: geometry (f8573a9c: object แยก 35,896 v, vpm2 10.98M —
   มากกว่าครึ่งของ asset) กับ normal map 8K (8e006d2e: `shoe_N` 8192²). ทั้งคู่ผ่านตลาด;
   จุดตัดคือระยะกล้อง — คำถามพิกเซล (ข้อ 5 ด้านล่าง).
5. **แก้วระดับส่งงาน = ไม่ใช้ Principled เปล่า**: BSDF_GLASS/Transmission + **LIGHT_PATH
   →TRANSPARENT สำหรับ shadow ray** + **VOLUME_ABSORPTION สำหรับสีแก้ว** + ของเหลวเป็น
   mesh ปิดแยกชิ้น (Water 130 v). พบใน 2/4 vase.
6. **EMPTY root ชื่อ asset** (9/11 assets — ยกเว้น ficus/olive ที่ไม่มี root); ใน 7/11
   mesh ลูกทุกตัว loc=(0,0,0) — transform อยู่ที่ root ชิ้นเดียว. ข้อยกเว้นจริง 2:
   leather shoe วางข้างขวาด้วย loc บนลูก (คู่ของ shared mesh), perfume1 วางโลโก้/จุกด้วย
   loc จริง.
7. **colorspace มีวินัยเกือบหมดแต่ไม่หมด**: data map (Normal/Rough/Opacity) = Non-Color
   ใน 9/11; ผิด 2 asset: **f8573a9c ติด sRGB บน normal+roughness** และ **8e006d2e ติด
   sRGB บน `sole_mask` ที่เข้า Roughness** (ของ pro ก็ผิดได้ — ต้องมีเครื่องตรวจฝั่งรับ).
8. **หนาแน่นตามความโค้ง ไม่ flat**: ใน slippers ตัวเดียว vpm2 ไล่ 3,021 (พื้น) → 84,538
   (แถบโค้งเล็ก); เครื่องรับของที่ตัดสินด้วย vpm2 ค่าเดียวต่อ asset จะอ่านของแบบนี้ผิด.

## delta vs โค้ดเรา (file:line) — ของ 5 assets กลุ่มนี้ที่อยู่ใน p2r91 แล้ว

**Δ1 — GLB roundtrip ฆ่า shader ที่เราจ่ายเงินซื้อ.** เส้นทางเราคือ .blend →
`bpy.ops.export_scene.gltf(export_apply=True)` (`pipeline/scripts/blenderkit.py:215`)
→ GLB → import. นับจาก node_hist: **19/39 materials ในกลุ่มนี้มี node ที่ glTF
ไม่มีที่ให้อยู่** (BSDF_GLASS, LIGHT_PATH, VOLUME_ABSORPTION, TRANSLUCENT, GROUP,
MIX_SHADER, TEX_NOISE/MAGIC-BUMP, DISPLACEMENT, VALTORGB/CURVE_RGB). พิสูจน์ในซีนจริง:
- `bookshelf_vase__acq0` (Carafe): ต้นทาง 7 nodes glass → ของเรา 2 nodes,
  **Base white + Roughness 1.0 + Metallic 1.0** = เหยือกแก้วเรนเดอร์เป็นโครเมียมด้าน.
  `bookshelf_vase__acq2` (Water) เหมือนกันเป๊ะ — น้ำกลายเป็นโลหะ.
- `wardrobe_vase__acq0` (Sage vase): GROUP procedural speckle → principled เปล่า
  ขาวล้วน Roughness 0.514. ลาย speckle ที่เป็นชื่อ asset หายทั้งใบ.
- `wardrobe_perfume__acq3` (Logo_1): MIX principled + image → **ดำล้วน ไม่มี image**.
- `deco_plant__acq0` (frond): Alpha รอด (exporter ยัด opacity เข้า basecolor-alpha)
  แต่ **BSDF_TRANSLUCENT หาย** — ใบทึบแสง; และ `_Gloss` โดน route เข้า Metallic
  (`MATH<SEPARATE_COLOR<...>>`).
- `wardrobe_shoes__acq0` (lace): `BUMP<PROC:MAGIC>` → Normal [0,0,0]; mat `shoe`:
  เกรดสี CURVE_RGB/HUE_SAT + SSS 0.146 → หายหมด.
  ที่รอด: `Glass.003` (b4d3ed11) เพราะต้นทางใช้ Principled Transmission อยู่แล้ว
  (VOLUME_ABSORPTION ยังหาย). ตรงกับ memory note "ห้ามลบ .orig.blend — Cycles material
  ของจริง" — ตอนนี้มีเลขยืนยันแล้วว่าหายจริง หายเท่าไร ชิ้นไหน.
**Δ2 — `export_apply=True` bake SUBSURF ที่ VIEWPORT levels ไม่ใช่ render levels.**
14/17 objects ที่มี SUBSURF ในกลุ่มนี้ตั้ง viewport=1 / render=2 (ใน 5 assets ที่อยู่ใน
p2r91 คือ 7/10; ที่เหลือ — laces ×2, Water — ตั้ง v2=r2 จึงไม่เสียตอน bake). ของเรา:
`bookshelf_vase__acq0` = **1,474 v = level-1 ของ cage 370 v เป๊ะ** (ตั้งใจให้เรนเดอร์
~5,900); `wardrobe_vase__acq0` 2,274 = L1 ของ 562 เป๊ะ; `wardrobe_perfume__acq0` 9,154 =
L1 ของ 2,304 เป๊ะ. **เราเรนเดอร์ทุกชิ้นที่ตั้ง viewport<render ที่ 1/4 ของความละเอียด
ที่คนปั้นตั้งใจ (Carafe, sage vase, ตัวขวด perfume)** —
แก้ได้บรรทัดเดียวใน `EXPORT_SCRIPT` (`blenderkit.py:209-216`): เซ็ต
`levels = render_levels` ก่อน export.
**Δ3 — คู่ที่แชร์ mesh ถูกแตกเป็นสองก้อน**: ต้นทาง shoe_low users=2; ของเรา
`wardrobe_shoes__acq2/3` users=1 ทั้งคู่ (17,944 v ×2) — เปลือง RAM อย่างเดียว แต่บอกว่า
instancing ไม่รอดท่อ.
**Δ4 — lathe ของเรา bake ตายที่ 32 เหลี่ยม**: `trn001_styling.py:119`
`def lathe(profile, cx, cy, z0, seg=32, scale=1.0)` + comment `:101` ("32-segment lathe
is a 32-gon"). Pro เก็บ cage 32-seg แล้วให้ SUBSURF r2 ทำ silhouette ~128-seg ตอนเรนเดอร์
(sage: เก็บ 562 v ได้ผลเทียบ ~9,000 v ของแบบ bake). R8 บอก vase เป็นคลาส BUILD ของเรา
— วิธี build ที่ถูกคือ **lathe หยาบเป็น cage + SUBSURF live** ไม่ใช่ lathe ละเอียด.
**Δ5 — เกณฑ์รับของที่ `asset_scale.py` ยังไม่เช็ค** (ปัจจุบัน: band ขนาดต่อคลาส
`asset_scale.py:548`, มี/ไม่มี PBR maps `:500,:536`, ความหนาแน่นพอสำหรับ cover
`mesh_density.py:190`): (ก) colorspace ของ data maps — f8573a9c พิสูจน์ว่าของ paid
ก็ติด sRGB ผิด ๆ มาได้; (ข) node-survivability preflight — สแกน node_hist ของ
.orig.blend ก่อน export: เจอ node เสี่ยง → ธง "ต้อง import จาก .blend หรือ rebuild
shader" ไม่ใช่ปล่อยผ่านเงียบ; (ค) trade-dress scan — `8f19d91a` (full_plan!) มี mat
ชื่อ `LV_texture` + image monogram; licence ไม่เคลียร์ trade dress
(`docs/LICENSING.md`) และของเราใช้ f8573a9c เป็น hero bag ใน tw1 แล้ว
(`build_room.py:5616` `_WARDROBE_BAG_MODEL`); (ง) ngon_share ≤0.005 + UV≥1 เป็น floor
รับของ (ระดับ asset กลุ่มนี้ผ่านหมด — max 0.001 ตาม `qa/blenderkit-study-stats.json`; ระดับ mesh มี
Circle.127 ที่ 0.0069 — ตั้ง floor ที่ระดับ asset); (จ) plant class ต้องมี opacity map
(Alpha=IMG) + translucent term — เช็คได้จาก dump ก่อนซื้อ (hypothesis จาก n=2 — ดูกฎ 5).

## กฎ transferable จัดอันดับ

1. **ซื้อของแล้วอย่าให้ท่อฆ่า**: ทุก hero asset ที่ shader มี node นอกชุด glTF
   (19/39 ในกลุ่มนี้) ต้องเข้าซีนจาก `.orig.blend` (append/link) หรือ rebuild shader
   หลัง import — ห้ามผ่าน GLB เงียบ ๆ. หลักฐานความเสียหาย: แก้วเป็นโครเมียม,
   vase ลายหาย, โลโก้ดำ, ใบไม้ทึบแสง — ทั้งหมดอยู่ใน p2r91 ตอนนี้.
2. **เซ็ต SUBSURF levels=render_levels ก่อน export_apply** (`blenderkit.py:215`) —
   ตอนนี้ Carafe / sage vase / ตัวขวด perfume ในเฟรมคือ level-1 bake = 1/4 ความละเอียด
   ที่จ่ายเงินซื้อ (Water และ laces ตั้ง v2=r2 จึงรอด).
3. **vase (คลาส BUILD เดียวของกลุ่ม): lathe เป็น cage 32-seg + SUBSURF r2 live**
   — เก็บ ~500–2,300 v ได้ silhouette 128-seg; เลิก bake 32-gon ตายตัว
   (`trn001_styling.py:119`).
4. **แก้วส่งงาน = Transmission + LIGHT_PATH shadow trick + VOLUME_ABSORPTION +
   ของเหลวเป็น mesh ปิดแยก** (Water Pitcher: 614 v ทั้ง asset — ราคาถูกมาก
   มูลค่าอยู่ที่ shader ล้วน ๆ).
5. **ใบไม้ = photo alpha card + TRANSLUCENT, เย็บรวม mesh เดียว** — งบเป็น
   **HYPOTHESIS จาก n=2 (ficus, olive) ไม่ใช่ band ยืนยัน**: พุ่ม 0.8–1.1 ม.
   = 31k–84k v + atlas 22–29 ใบ ≤4K; เงื่อนไขยืนยัน: probe potted_plant เพิ่ม ≥3 ตัว
   ภายในวันที่ 22 (2026-09-22) ก่อนใช้เป็นเกณฑ์รับของ. อย่า instance ต่อใบ อย่าปั้นใบ
   (ยืนยัน R8: ของที่ซื้อคือภาพถ่าย ไม่ใช่ mesh).
6. **ของคู่สร้างข้างเดียว**: MIRROR หรือ shared mesh (users=2) — และตรวจว่าท่อ ingest
   ของเรารักษา users ไว้หรือแตก (ตอนนี้แตก).
7. **เกณฑ์รับของเป็นเลขจากกลุ่มนี้**: ngon_share ≤0.005 (ระดับ asset) · UV ≥1 ทุก mesh ·
   data map = Non-Color · dims เข้า band คลาส · plant ต้องมี opacity+translucent
   (hypothesis n=2 — ดูกฎ 5) · ชื่อ material/image ผ่าน trade-dress scan · ไม่มี
   LOD/shape key ให้คาดหวัง (จาก 11 ตัวนี้ — อย่าสรุปทั้งตลาด).
8. **ตะเข็บหนัง: เลือกสำนักตาม px จริง** — geometry stitch (10.98M vpm2) สำหรับ hero
   ระยะใกล้, 8K normal map สำหรับระยะชั้นวาง; ห้ามตัดสินก่อนวัด px/mm ของ crop.
