## What the source is

Two screenshots of one printed sheet shown in a design crit. Structure: **one row per precedent**,
**one column per analysis lens**, and **two terminal synthesis rows** that close the table. The
worked example carries three kindergartens — so the *data* is institutional, not residential; the
*schema* is the transferable part.

## The two synthesis rows — the step that makes this a method

The table is closed by two rows that run across every column **except the row-label column** (col. 1,
`ชื่อโครงการ`, which in these two rows carries the row's own name) ([S1] and [S2], bottom two rows):

| Row | Thai | Meaning |
|---|---|---|
| A | **สรุป** | summary — what this column's evidence, read across all precedents, adds up to |
| B | **แนวทางการนำไปใช้** | the approach for applying it — what we will *do* with that finding |

Row B is the load-bearing one: it is per-column, not a single closing paragraph, so every lens
(Function, Layout, Lighting, Colour, Material…) must terminate in a stated design consequence.
A precedent study without row B is a report, not an input.

**Honest limit:** in the source both rows are **empty** — outside the col.-1 label cell (`สรุป` /
`แนวทางการนำไปใช้`), every cell carries only the red placeholder text (below). The sheet therefore
specifies the required *form* of the synthesis; it does not demonstrate a filled-in example of it.

## Cell-content convention (the red placeholders)

Cells whose content is still outstanding are marked in red with what that cell must eventually hold:

- **`ข้อความ`** ("text") — text-only cells. Seen in the empty `User` and `Function` cells
  ([S1], rows 2–3).
- **`ข้อความ+รูปภาพ`** ("text + image") — cells that must carry prose **and** imagery. Seen in the
  empty `Lighting` cells (all three rows) and the trailing-column cells (rows 2–3) on [S2], and in
  every cell of both synthesis rows **except the col.-1 row-label cell** ([S1], [S2]).

Placeholder-only (nothing else in the cell): `Lighting` (rows 1–3, [S2]), the trailing column
(rows 2–3, [S2]), `User` and `Function` (rows 2–3, [S1]).

Partially filled: the `Space` cells ([S2], rows 1–3) each carry **two interior photographs *and*
the red `ข้อความ+รูปภาพ` placeholder beneath them** — the image half is done, the text half is not.
So the placeholder marks an outstanding half, not necessarily an empty cell.

The sheet's own rule for the synthesis rows is therefore: text *and* image, in every column that
takes content.

## The Color column — a stacked bar with one percentage annotation

Each precedent's `สี / Color` cell is a **vertical stacked bar**: tinted bands above a bottom block
([S2], col. `สี`, all three rows). Literally, what the sheet prints:

- The bottom block is drawn **blank/white** and carries the text **`50%`** — in all three rows.
- Measured on [S2], that blank block occupies **~41–47%** of the bar's height in the three rows, so
  the drawn height agrees with the printed 50%.
- Tinted band count differs per precedent as observed: 5 bands (row 1), 3 (row 2), 6 (row 3).
- The sheet prints **no legend, no key and no colour names**, and no percentage on any of the tinted
  bands. The annotated block is assigned **no colour at all** — whether it denotes white/neutral *as
  a colour* or an *unfilled area of the bar* is not stated by the source.

A proportion reading is what the sheet supports (a percentage is printed on a block whose drawn
height matches it). Any further naming of that proportion is ours, not the sheet's — see
§Studio reading.

## The Description block — 8 fixed fields per precedent

The `รายละเอียด / Description` cell is a fixed fact block, in this order ([S1], col. 2):

`เจ้าของโครงการ` owner · `ผู้ออกแบบ` designer · `พื้นที่ใช้สอยรวม` total usable area · `ปรัชญาการสอน`
teaching philosophy *(a building-type-specific field — the operating doctrine of the client
institution)* · `ห้องเรียน` classrooms · `จำนวนนักเรียน` occupant count · `เริ่มโครงการปี` year started ·
`เปิดใช้งานปี` year opened.

Unknown fields are written **`N/A`**, not left blank — the sheet keeps the field and admits the gap.

## The Site Analysis cell — 4 parts

Locality map + aerial/context photo pair · address line · **`ระบบโครงสร้าง`** (structural system) ·
2–3 lines of prose on the building's form and how it meets the outdoors ([S1], col. 3).

## Where precedent evidence must come from (by project type)

The course handout keys a **data-access rule** (`การเข้าถึงข้อมูล`) to the project's type
(`knowledge/_inbox/discord/MY-DATA-PEAT/thesis/001_thesis/files/483669_-64.pdf`, the
การเข้าถึงข้อมูล row of each type's criteria table). Case studies (`กรณีศึกษา`) are named in that row
for **type 3 only**, where they are the primary source (`เป็นหลัก`), mixed domestic + international.
For types 1 and 2 the row names the owner/project architect and the owner/occupants respectively as
the required data source, and says **nothing about case studies** either way — the handout is silent
on their role there, and this file does not fill that silence in.

| Project type (as printed) | Data-access rule (source's words) | Reading |
|---|---|---|
| 1. โครงการออกแบบสถาปัตยกรรมภายใน — *Interior Architecture for…* (p.4) | *"ต้องสามารถติดต่อ หรือรับข้อมูลจริงของโครงการจากเจ้าของหรือสถาปนิกโครงการ"* | real data from the **owner or the project architect** |
| 2. โครงการปรับปรุงการออกแบบสถาปัตยกรรมภายใน — *Interior Architecture Renovation for…* (p.5) | *"ต้องได้รับข้อมูลจากเจ้าของและผู้ใช้งานในพื้นที่"* | from the **owner *and* the people who occupy the space** — the occupants are a named, non-optional source |
| 3. โครงการเสนอแนะการออกแบบสถาปัตยกรรมภายใน — *Interior Architecture Suggestion for…* (p.5) | *"ต้องหาข้อมูลจากกรณีศึกษาแบบผสมผสานเป็นหลักทั้งในและต่างประเทศ"* | when the project is hypothetical, **case studies are the primary source** — and mixed **domestic + international**, not one or the other |

The same handout lists *"มีกรณีศึกษามาก"* (many case studies exist) as one of type 3's
*ความน่าสนใจของโครงการ* — the project's **interest/appeal** criteria — alongside *"มีความใหม่"*
(newness) and *"สามารถเลือกอาคารและที่ตั้งให้สอดคล้องได้"* (p.5). *(Our reading, not the source's:
this makes precedent availability a screen on the topic itself, not only research material. The
handout's own category is interest/appeal; it does not use the words "test" or "viability".)*

## Studio reading (ours, not the source's)

The source is a design-school sheet and says nothing about this repo. Our own reading, flagged as
such: the matrix is a candidate structure for the pre-concept precedent step — one row per
reference project, the 11 lenses as the fields, and `แนวทางการนำไปใช้` as the mandatory output that
hands a stated design consequence to the concept.

**Our inference on the Colour column (the source does not say this).** We read the annotated 50%
block as a **dominant share** and the tinted bands above it as **accents** — i.e. a palette recorded
as *proportion*, which is the form a spec can consume, rather than a flat colour list. This is an
inference, and a load-bearing part of it is unsupported: the sheet prints no legend and no colour
names, and the annotated block is drawn blank, so it may equally be an unfilled area rather than a
"dominant colour". What the source does support is only that **one** block of the bar carries a
percentage and is drawn at roughly that share of the height. If we adopt the dominant-plus-accents
form, we adopt it as a studio convention, not as a promoted finding.
